(`UglyToad.PdfPig.Filters.Jpx.OpenJpeg/OpenJPEG`); the tests, benchmarks and tools have none. Paths are relative to
`OpenJPEG/`, line numbers as of commit `caf801e` (before the symbol removal). Generated by searching the source; review each item before
changing it, and keep the decoder bit-exact (`.claude/skills/verifying-jpx-decoder-changes`).

### Removed

`TEST_MATH_MODE`, `TWO_PASS_VERSION`, `STANDARD_SLOW_VERSION`, `ENABLE_EMPTY_PACKET_OPTIMIZATION`,
`SUPPORT_DUMP_FLAG`, `DEBUG_STREAM` and `NET45` were never defined. Their blocks are gone and the branch that was
compiled is kept, so the built code is unchanged:

- `TEST_MATH_MODE` (explicit `(float)` casts after every float operation): the 32-bit .NET Framework note is in the
  README ("Platform notes").
- `TWO_PASS_VERSION`, `STANDARD_SLOW_VERSION` (with the 2.1 helpers `Decode_1`, `Interleave_v` it kept alive),
  `ENABLE_EMPTY_PACKET_OPTIMIZATION`, `SUPPORT_DUMP_FLAG`: upstream variants its default build leaves out, recorded
  under "Deliberate differences" in `OpenJPEG/UPSTREAM.md`. `DPARAMETERS.DUMP_FLAG` stays (public) and has no
  effect.
- `NET45`: the .NET 4.0 `BinaryWriter` constructor stays, so disposing `BWrite` still closes the caller's stream
  (TGA export). Passing `leaveOpen: true` would change that behaviour: decide separately.
